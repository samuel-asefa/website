# samuelasefa.vercel.app

Personal site of Samuel Asefa: robotics, software, research, and teaching.

The site keeps its original design (dark theme, Outfit, sky-blue accent, glass cards, bento grid, animated circuit background) and its original page addresses. Underneath, every page is now rendered to static HTML at build time from typed content files, so the text is in the page itself (good for search and for visitors without JavaScript), and JavaScript adds the interactive parts.

## What's new compared with the previous version

- **Project detail pages** at `/projects/<slug>.html` for 11 projects: overview, role and team, key numbers with their conditions, publications with honest status, sections (context, design, process, results, reflection), figures with captions, resources, related projects.
- **Homepage**: featured projects, an interactive RoboRoute demo, a recognition strip, and the Skills & Technologies section the Explore card linked to (it didn't exist before). The typed-text line under the title now works.
- **Projects page**: corrected and expanded descriptions, research status labels (preprint, accepted talk), a key metric per project, Details buttons, image galleries, counts on the filters, and linkable filters (`/projects.html?category=research`).
- **Awards**: Individual / Team badges and filters, links to related projects, accessible image and PDF viewer.
- **Education**: school header, keyboard-accessible tabs (linkable with `#ap-scores`), GPA labelled as the average of yearly GPAs.
- **About**: expanded bio, a Teaching & Community section, the same photo carousel (Swiper now installed from npm at a pinned version and loaded only on this page).
- **Experience**: links from each role to related project pages.
- **Contact**: copy-email button, validation, and a clear note that the form opens a draft in your email app (nothing is sent by the site).
- **Fixes**: one configured site address for canonical/Open Graph tags (the old `samuelasefa.com` canonical didn't resolve), a broken GitHub link, responsive WebP images (the old pages loaded multi-megabyte originals), a sitemap and robots.txt, keyboard and screen-reader support for the menu, modal, tabs, and filters, reduced-motion support, and card grids that fit 320 px phones.

## Local development

```bash
npm install
npm run dev        # http://localhost:5173; content and template edits apply on reload
npm run build      # type-checks, then builds to dist/
npm run preview    # serves dist/ like a static host
npm run check      # checks dist/: titles, descriptions, canonicals, share images, alt text, internal links and #anchors
npm run check -- --external   # also requests every outbound link
npm run media      # regenerates responsive images after adding or changing an image
```

Node 18.18 or newer.

## Deployment assumptions

- Output is static files in `dist/`. On Vercel the Vite defaults work: build `npm run build`, output `dist`.
- The production address is set once in `src/config/site.ts` (`https://samuelasefa.vercel.app`). Override with `SITE_ORIGIN=https://example.com npm run build`, e.g. after connecting a custom domain.
- Page addresses are unchanged: `/`, `/about.html`, `/experience.html`, `/education.html`, `/awards.html`, `/projects.html`, `/contact.html`. New: `/projects/<slug>.html` and `/404.html` (Vercel serves it for unknown paths).
- Fonts and icons load from Google Fonts (Outfit) and cdnjs (Font Awesome 6.4.0), as before.

    pages/*.ts            one file per page

## Editing content

All copy lives in `src/content/*.ts`; templates never need to change for content edits. Text fields accept a little inline HTML (`<a>`, `<em>`, `<strong>`, `<code>`). Leave a field out rather than guessing; every template treats optional fields as optional.

- Numbers go in `facts` with the condition that makes them true, e.g. `{ value: '66.2%', label: 'lower RMSE than a standard EKF', condition: 'severe degradation, in simulation' }`. The first fact appears as the metric pill on project cards.
- Awards and recognition carry a `scope`: `individual` or `team` (shared with teammates or co-authors).
- Research uses `publications` with a `status` (`preprint`, `peer-reviewed`, `conference-talk-accepted`, …) and a plain-language `statusNote`.

## Adding a project

1. Put its images in `public/images/projects/<slug>/` (the folder named after the project's slug).
2. Add an entry to `src/content/projects.ts`. Required: `slug`, `title`, `line` (card description), `category`, `depth`, `dates`, `start`.
   - `depth: 'entry'`: a card on the Projects page that links straight to the project's first link.
   - `depth: 'overview'` or `'case-study'`: a card plus its own page at `/projects/<slug>.html`. Add whichever `sections` you can support; missing ones are skipped.
3. To control where it appears on the Projects page, add its slug to `ORDER` in `src/render/pages/projects.ts` (otherwise it goes last in its category).
4. To feature it on the homepage, give it `featured: <position>` (the featured grid is designed for three).
5. Run `npm run media`.

## Media conventions

- Originals live in `public/images/`, one folder per part of the site:

  ```
  public/images/
    projects/<slug>/   each project's images, slides, and original video files
    awards/            certificates, letters, medals, award PDFs
    skills/            skill icons
    experience/        square organization logos for the Experience page (256px)
    schools/           university seals for research mentors
    education/         school logo
    site/              profile photo and footer icons
    archive/           files the site doesn't use (kept, not deleted)
  ```

  Images shown on several pages live with the project they come from (the ARC team photo is in `projects/rocketry-airbrakes/`). File names must stay unique across folders, because generated files in `public/media/` are named after the file alone.
- Originals are never modified. `npm run media` writes WebP versions at 160, 480, 800, 1200, 1800, and 2400 px (never upscaled, EXIF rotation applied, transparency kept) and a 1200×630 JPEG for link previews, and records dimensions and a placeholder colour.
- Use `photo()`, `figure()`, or `screenshot()` from `src/content/media.ts`. Figures (charts) are never cropped and sit on a white mat; captions say what the image shows.
- A project's `gallery` holds extra images that appear only in the image viewer, right after the cover (for example, an early prototype).
- Every image on a project page can be enlarged; the modal links to the original file (or, for originals over 8 MB, to the largest web version).
- **Videos**: browsers don't reliably play `.mov`. Convert clips to H.264 MP4 with a poster frame and put both in `public/media/video/`, then add a `video` block to the project (optionally with `beside` to show it next to a photo), or a `videos` block to show several clips side by side. With ffmpeg:

  ```bash
  ffmpeg -i clip.mov -c:v libx264 -crf 24 -pix_fmt yuv420p -c:a aac -b:a 96k -movflags +faststart public/media/video/clip.mp4
  ffmpeg -ss 2 -i clip.mov -frames:v 1 -vf scale=720:-2 public/media/video/clip-poster.jpg
  ```

  Videos show controls and never autoplay; nothing downloads until a visitor presses play.

## Interaction notes

- **Background, orbs, cursor, loader**: same as before. The canvas now handles resizes and high-DPI screens, pauses in background tabs, and draws one still frame with reduced motion. The cursor ring only appears with a mouse/trackpad. The loader hides itself even if JavaScript fails.
- **Image modal**: the original look, now a proper dialog: focus moves into it and stays there, Escape or a backdrop click closes it, arrow keys switch images, and focus returns to what opened it.
- **RoboRoute demo**: drag waypoints, use arrow keys on a focused waypoint (Shift = 6 in), or type coordinates. It computes distances, headings, turns, and the same `setPose`/`moveToPose` lines RoboRoute exports, and says plainly that it doesn't simulate a robot.
- **GitHub section**: the same three cards and calendar; cached for 30 minutes; if GitHub rate-limits or fails, it says so instead of showing numbers.
- Content never depends on JavaScript: fade-ins are added by script only for elements below the fold, and everything is visible without them.
